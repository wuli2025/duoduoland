# 多多群岛

本地活动与分层名片演示：78 位独立人物（含18位新增AI创业者/工程师）、10 场主题活动、16 个职位。暖白、黑色与亮黄，系统字体，自绘线性图标。所有报名、招呼、收藏及投递都是保存在当前浏览器中的演示操作。

## 两种打开方式

**离线使用**：双击 `index.html`。普通脚本挂在 `window.BJ`，无需安装依赖、构建或联网。推荐和意图解析使用本地规则，匹配页明确显示本地引擎。

**大模型推荐**：安装Node 24，将接口配置填写在项目根 `.env.local`（参照 `.env.example`），双击 `启动演示.bat`。脚本运行 `node server/index.js --open`，服务端就绪后打开实际监听地址。默认从8787开始，占用则自动尝试8788、8789等，最多10个端口；控制台打印实际URL，前端始终使用同源相对接口。也可以手动运行 `node server/index.js`。

服务端环境变量优先于 `.env.local`：`OPENAI_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`PORT`、`LLM_TIMEOUT_MS`、`LLM_CONCURRENCY`、`LLM_REASONING_EFFORT`、`LLM_MAX_OUTPUT_TOKENS`、`LLM_CACHE_TTL_MS`、`LLM_CACHE_ENTRIES`。默认监听 `127.0.0.1:8787`，超时60000ms，并发2，推理强度low，输出上限2600 tokens；仅网络失败最多重试一次，共用同一个时间预算。不支持reasoning参数的接口会明确记录兼容事件并移除该参数重发。

匹配页在线时先展示黑色细线圆环与亮黄轨道点：读取实际公开名片数量 → 本地召回实际候选 → 模型评估。阶段由计算和请求回调推进，不用定时器假装进度；计时从真实重排POST发出开始，不包含health协商。等待期间可修改筛选或意图，返回后才依次展示Top5；失败则展示本地Top5和“重试”。file或关闭LLM时直接显示本地结果。

继续使用现有 `.env.local` 中的API和模型，不切换提供方。`/api/health`返回公开模型名和超时；重排响应meta包含`model/durationMs/cached/cachedAt/correlationId`，另含原计算时间`upstreamMs`、完成时间及来源请求号。页面显示服务端模型、耗时、时间；缓存命中明确显示“使用x分钟前的大模型结果”，不会把毫秒级缓存访问当作模型计算。“重新计算”发送`bypassCache:true`，不复用缓存或进行中的旧请求，会真实调用上游并更新缓存。默认缓存5分钟（64条，内存缓存，TTL设0可关闭）。

无需结束占用端口的其他进程。可用 `PORT` 改起始端口，`PORT_ATTEMPTS` 改尝试数量（最多100）。每次占用记录 `PORT_IN_USE`，范围耗尽记录 `PORT_RANGE_EXHAUSTED` 并非零退出，其他监听错误记录 `LISTEN_FAILED`。例如：

```powershell
$env:PORT='8788'
$env:PORT_ATTEMPTS='5'
node server/index.js --open
```

## 推荐流程与隐私

本地matcher读取公开名片并召回Top10（仅显示候选头像）→ 服务端Responses接口重排 → LLM 0.6 / 本地0.4融合 → MMR选出至多5人 → 按最终分数稳定降序展示。配置入口：`src/config/matching.js`、`src/config/reasons.js`、`src/config/llm.js`；提示词位于 `prompts/`。

界面只读状态机idle→reading→recalled→llm-pending→done/cached/failed。失败显示“推荐服务暂未响应，已改用本地规则”；file或关闭LLM时完全不请求。重新匹配和离开页面中止旧请求；服务端在所有等待方取消后中止上游并释放并发槽。意图解析也返回并显示实际引擎。

新增AI工程师覆盖预训练、推理部署、RAG、Agent、多模态、机器人、安全、数据、MLOps及推荐搜索。技术需求按公开技能覆盖率计分；行业、合作方式、To B/C、全职/业余、城市、报酬和入职状态参与双向匹配。兼职顾问与全职CTO条件冲突会降分，隐藏字段不参与计算。

前后端分别按公开版本与字段白名单过滤原始档案，自己的意图也裁剪为必要字段。缓存键包括候选集合/公开状态、本地分、招呼/见面状态、双方公开投影、意图、模型、提示词及理由策略。模型只收到公开内容和数值分数；签到、开放聊天、公开意图标记、招呼/见面状态不进入提示词。联系方式、头像路径、完整档案、其他场次记录不发送；明确标记的微信/QQ也脱敏。

职业推荐理由最多40字、破冰问题最多20字，要求姓名加完整行业、技能、offer或合作条件；兴趣、简介、经历不能单独放行。称呼统一为“你”，残留“您”在输出校验时替换。禁用措辞在 `src/config/reason-policy.js`；命中内部措辞或缺证据时，仅该条理由回退为本地生成并记录，保留模型分数。回退按完整证据和姓名预算选短模板，破冰句保留完整问句；无法安全修复或仍重复只移除该候选，返回明确的dropped ID。所有条目被移除、结构错误或非法分值时整次降级。评估报告列出严格证据检查与回退/移除数量。

错误日志由 `server/error-log.js` 统一出口，包含关联id、操作、具名错误和时长；HTTP与LLM跨层不重复记录。规则版本集中在 `server/cache-versions.js` 与 `reason-policy.version`，对应配置变更时需提升版本；缓存键不再序列化整个配置模块。

`GET /api/health` 不输出密钥。静态托管仅允许入口、src 与 assets，`.env.local`、server、prompts 和 docs 无法经 HTTP 读取。本地数据是演示夹具，不能把浏览器中包含演示数据理解成生产环境的访问控制。

## 恋爱交友

输入“找男朋友”“想认识女生”“找对象”等会进入恋爱交友模式；普通“交朋友”仍按原社交规则。“年龄相仿”按自己的年龄±5解析，“比我大/小一点”与明确年龄段也支持。年龄按 `src/config/dating.js` 的演示参考年份2026计算，所有交友均限定成年人。

林知夏默认未开启交友。在活动的“本场设置”第2步选择“找对象”模板后，点击“切换交友版并开启本场交友”，才会为该场次授权。可拒绝；拒绝后没有恋爱结果，也不请求模型重排。修改基础资料中的性别、出生年份、感情状态、交友偏好、生活方式和价值观，以及交友版字段开关，可调整公开范围。跨活动需要分别开启；旧浏览器存储迁移默认关闭。职业版禁止公开这组敏感字段。

78人均有虚构人物设定；24位单身人物明确公开交友版（男女各12，24–36岁），主要参加读书、音乐、徒步、设计和早午餐活动；AI之夜仅少量开放者。其余54人不进入恋爱匹配。基础性别和出生年份依据头像日志的文字设定，无头像者另行编写，不从照片判断。

硬条件先于本地评分和模型：双方本场交友版公开必要字段、单身、同意交友、目标性别/年龄符合，而且双方偏好互相接受。未公开性别或年龄等必要字段的人不参与。共同兴趣、生活节奏、价值观、同城、年龄接近与意图计分；职业权重为0。人数不足5人只返回实际人数，按同样双向条件推荐其他活动及人数。

每张结果卡和右侧详情均展示“为什么他/她可能适合当你男朋友/女朋友”。在线由原API生成 `fitReason`（≤60字），引用双方公开兴趣或生活信息，不评价外貌，不拿收入/职级作卖点，不保证关系结果。缺乏双方证据、超长或命中禁用词时仅该条回退本地模板，服务端记录 `FIT_REASON_FALLBACK`；file和服务失败直接采用共同兴趣模板并标明本地引擎。提示词在 `prompts/rerank-dating.md`，词表/权重/模板/磨合点开关在 `src/config/dating.js`。

更新本轮代码后，**请重启你手动打开的服务窗口**以加载新的服务端 schema 与提示词，然后刷新页面。验收使用独立的8788端口实例，未关闭原8787服务。

## 意图设置与服务版本（第9轮）

首次设置与未设置的活动默认空白，预报名的AI之夜也不预填职业需求。已保存的用户意图保留。空意图的匹配页先提示写一句或点选标签，不调用模型重排。

第2步显示本场公开名片中的常见标签，按人数排序取前16项。一位参会者的重复标签只计一次；相同文字来自行业/技能两个字段时注明类型。点选或移出胶囊会同步更新意图和公开预览，角色写入seekRoles、行业写入seekIndustries、技能写入seekSkills；交友兴趣、生活方式、价值观分别写入interests/lifestyle/values。职业/交友按钮切换标签统计范围；交友只统计本场公开且已开启的名片。解析与点选的标签都可删除。

本地关键词是恋爱模式与目标性别的安全依据：旧接口遗漏mode/targetGender或返回冲突性别时保留本地解析，排名入口再依据原文核对，客户端失败回退前也过滤不合格性别。手动删掉目标性别或年龄标签，会同时去掉原文的对应关键词，避免后续又被解析回来。

版本号位于 `src/config/llm.js` 的 `appVersion: '10.0.0'`。服务进程启动时记录该版本，通过 `/api/health` 返回；缺版本或不一致时，设置和匹配页提示重启，dating只用本地规则。用户8787服务由Claude负责重启；验收仅启动自己的实例并自动顺延端口。更新服务后刷新页面即可重新协商版本。

本地交友fitReason提供8套模板，按共同兴趣、生活方式、价值观、同城、年龄接近等公开证据组合，Top5内避免复用模板，仍受60字及公开证据约束。配置入口为 `src/config/intent.js` 与 `src/config/dating.js`。

## 活动参会者

详情页与活动卡片显示报名和签到人数。报名总数使用活动登记演示值；签到数按实际公开名单统计，并在详情和卡片提示中说明口径。头像墙签到优先、最多24位，剩余显示+N；卡片叠放4人。名单小于报名总数时显示“展示其中m位已公开名片的参会者”。hover显示公开姓名/职位，点击打开本场投影名片；未公开头像显示首字占位，隐藏字段显示锁。人数上限在`src/config/app.js`配置。

## 第10轮：多多群岛与居中轮播

品牌统一为「多多群岛」，由 `src/config/app.js` 控制标题、页首、页脚及名片字标，分享地址为配置中的 `duoduo.example` 演示域名。保留原存储键与 `window.BJ`，已有名片不因改名丢失。当前 `appVersion=10.0.0`；旧服务窗口重启后健康检查才会返回新版。

字号集中在 `assets/css/base.css`：正文16px、辅助13–15px、卡片20px、区块28px、页面48–52px；标题800、正文500。深浅背景使用不同的说明文字颜色。1024宽度活动网格改为三列，名片与推荐正文随内容撑开。

首页「精选 / 本周 / 榜单」轮播分别取编辑推荐、上海时区本周一至周日的活动、报名数降序。日期来自活动 `startDate`（演示活动为2026年10月）；实际本周无活动时明确展示空状态。中间卡片占54%，两侧露出相邻活动；5秒自动切换，鼠标悬停、焦点进入、弹层打开时暂停。支持箭头、圆点、键盘、侧卡点击、触控与拖拽；系统减少动态效果时关闭动画和自动播放。

配置入口 `src/config/carousel.js`，数据逻辑 `src/core/carousel.js`，可复用挂载组件 `src/ui/carousel.js`，样式 `assets/css/carousel.css`。`node --test tests`包含轮播边界与数据源测试；`py -3 scripts/browser-round10.py`自行启动并仅关闭所属服务，截图及排版审计见 [第10轮验收](docs/verification-round10.md)。匹配页排版验收明确使用本地规则，没有伪造大模型响应。
