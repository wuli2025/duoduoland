## D. 大模型驱动推荐（用户要求：用其提供的 API 作为推荐算法驱动）
API：OpenAI Responses 兼容接口，配置在项目根 `.env.local`（已存在，包含 OPENAI_API_KEY / LLM_BASE_URL / LLM_MODEL）。**该接口不允许浏览器跨域（CORS 预检 403）**，因此：
1. 新增 `server/`（Node 24，零依赖）：
   - `server/index.js`：读取 `.env.local`（也支持环境变量），静态托管项目文件，监听 `127.0.0.1:8787`（端口可配置）。
   - `POST /api/llm/rerank`：入参 = 我的本场意图 + 我的本场公开投影 + 候选人列表（**仅本场公开投影**，服务端也再做一次字段白名单校验，绝不发送未公开字段、联系方式）。调用 `${LLM_BASE_URL}/responses`（model=LLM_MODEL），要求严格 JSON 输出：每个候选人 `{id, needAB, needBA, complement, common (0–1), score (0–100), reason (≤50字，必须引用对方公开信息), icebreaker}`。服务端校验 schema、id 必须属于入参、数值范围、截断长度；不合法则返回具名错误。
   - `POST /api/llm/intent`：把一句话解析为 `{seekRoles, seekIndustries, offer, city}`。
   - 可配置超时（默认 25s）、并发上限、最多 1 次重试（仅网络错误）；结构化日志（关联 id），**日志与错误信息中绝不输出 Key 或完整提示词**。`GET /api/health`。
   - 提示词模板放 `prompts/rerank.md`、`prompts/intent.md`，模板渲染，不在代码里拼死。
2. 前端 `src/core/llm-client.js` + `src/config/llm.js`（enabled、endpoint、timeout、candidateCount=12、融合权重）：流程 = 本地 matcher 召回 Top12（隐私投影）→ 调用 /api/llm/rerank → 与本地分数融合（权重可配，默认 LLM 0.6 / 本地 0.4）→ MMR → Top5。意图解析同样优先走 /api/llm/intent。
3. 降级：file:// 打开或服务不可用/超时/返回不合法时，自动使用本地规则引擎；匹配页右上角用一行小字如实标注当前引擎："由大模型重排" 或 "本地规则计算（未连接推荐服务）"。不能伪装成 LLM 结果。
4. 新增 `启动演示.bat`（`node server/index.js` 并打开浏览器 http://127.0.0.1:8787）与 `.env.example`（无真实 Key）。README 说明两种打开方式。
5. 测试：server 的 schema 校验、隐私白名单（构造含未公开字段的请求，断言发出的 payload 不含它们——用可注入的 fetch 假实现）、超时降级、融合排序。
