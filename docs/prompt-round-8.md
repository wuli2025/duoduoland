# 第 8 轮：支持"找男朋友/找女朋友"等恋爱交友意图（用户反馈：说要找男朋友，却推荐了一堆年龄偏大的职业人士）
保持全部既有约束（≤500 行、配置化、无 emoji / 无 AI 味元素、Bonjour 风格、隐私投影、不打印 .env.local 的 Key、不结束其他占用端口的进程）。
现状（Claude 核实）：engine.parseIntent('想找个男朋友，年龄相仿，最好也喜欢户外') → {"seekRoles":[],"seekIndustries":["户外"],...}；数据中没有性别、年龄、感情状态字段，所以只能按职业因子排序。

## 1. 数据（敏感字段，默认隐藏）
- 基础档案新增：gender（男/女/不公开）、birthYear、relationshipStatus（单身/恋爱中/已婚/不公开）、datingOpen（是否愿意在活动中认识恋爱对象）、datingPreference（想认识的性别、年龄范围、看重的点）。
- 这些字段默认不在任何名片版本的 visibleFields 中；新增可选名片版本「交友版」（主题色柔和），只有用户在该版本中主动打开才对外可见。名片编辑页对这几个字段加一句说明"仅在你选择交友版且开启后可见"。
- 按 docs/assets-log.md 中头像对应的人物描述（性别、年龄）为全部 78 人补齐 gender/birthYear；其中约 20–24 人设为单身且 datingOpen=true（男女各半，年龄 24–36，兴趣与生活方式各不相同），在本场选择「交友版」；主要分布在读书会、音乐、徒步、设计工作坊、早午餐等休闲活动，少量出现在 AI Agent 开发者之夜。其余人不开放（包括已婚/恋爱中/不公开），绝不能出现在恋爱匹配结果里。
- 「我」林知夏：女，约 30 岁，单身；新增「交友版」名片供她选择（默认未开启 datingOpen，选择交友意图时引导开启）。

## 2. 意图理解
- parseIntent 识别恋爱交友意图（男朋友/女朋友/对象/另一半/脱单/恋爱/约会/相亲 等，同义词进 config）：返回 mode:'dating'、targetGender、ageRange（"年龄相仿"= 我的年龄 ±5，"比我大/小"等可解析）、interests。LLM intent 接口同步支持这些字段（schema + 提示词）。
- 非恋爱意图保持原逻辑；不得让恋爱字段影响职业匹配。

## 3. 匹配规则（mode:'dating'）
- 硬条件（双向同意）：候选人 datingOpen=true 且本场所选版本公开了交友字段；单身；性别符合我的 targetGender；年龄在我的 ageRange；**我也符合对方的 datingPreference**（性别、年龄范围）；我本人也已在本场开启交友（否则提示我先开启，不展示结果或只展示说明）。
- 打分：共同兴趣、生活方式与价值观关键词、同城、年龄接近、双方本场意图互相匹配；职业因子权重显著降低（配置化，dating 权重组）。
- 理由与破冰：聚焦共同兴趣/生活，不评价外貌，不提及对方未公开的信息，不使用油腻或物化措辞；提示词与 reason-policy 增加对应规则。
- 人数不足：如实显示"本场公开愿意认识新朋友（恋爱方向）的人有 N 位"，不足 5 人时只展示 N 位，并推荐更适合的活动（按各活动中符合双向条件的人数排序，显示人数）。
- 隐私：恋爱匹配结果页只显示对方交友版公开的字段；性别/年龄若对方未公开则既不显示也不参与（不满足硬条件即不入选）。

## 4. 参加流程
- 本场设置第 2 步：当意图解析为 dating 时，提示"找对象需要你也公开交友信息，对方才能看到你的意愿"，一键切换到「交友版」并开启 datingOpen；用户可拒绝（拒绝则不进行恋爱匹配，说明原因）。
- 快捷模板增加「交朋友 / 找对象」。

## 5. 测试与评测
- node 测试：parseIntent 对「找男朋友」「想认识女生」「年龄相仿」「比我大一点」的解析；硬条件（性别、年龄、单身、datingOpen、对方偏好双向）；未开放者永不入选；非恋爱意图结果不受影响；人数不足时如实返回少于 5 人。
- docs/match-eval.md 新增画像：①林知夏「想找个男朋友，年龄相仿，喜欢户外」在 AI Agent 开发者之夜与城市徒步各跑一次（期望：全部为男性、单身、datingOpen、年龄在 25–35、共同兴趣命中；AI 之夜人数不足时如实提示并推荐徒步等活动）；②一位男性用户「想认识女生，一起看展」；本地与真实 LLM 都跑，如实记录。

## 7. 用户追加：每位候选人下方生成"为什么他适合当你男朋友"的理由
- dating 模式下，Top 列表每张卡片下方、以及右侧详情中，显示一段专门的理由，标题按对方性别与我的意图配置化（如"为什么他可能适合当你男朋友" / "为什么她可能适合当你女朋友"），内容 1–2 句（≤60 字）。
- 由真实大模型生成（rerank 输出新增字段 fitReason，dating 模式专用），必须引用双方公开的交友信息：共同兴趣、生活方式、价值观、作息/城市、双方本场意图的契合点；可以写一句可能需要磨合的地方（可配置是否显示），保持真诚克制。
- 禁止：评价外貌/身材、提及收入或职级作为卖点、油腻或物化措辞、提及对方未公开的信息、承诺"一定合适"；reason-policy 增加对应禁用词与证据校验；不合格时回退本地模板（基于共同兴趣），并如实记录。
- 本地规则（file:// 或服务失败时）同样生成 fitReason（模板化，引用共同兴趣），并标注当前引擎。
- 测试：fitReason 存在、长度、引用证据、禁用词拦截、非 dating 模式不出现该字段。
