## 2. AI 工程师偏向各不相同（用户追加需求 ②）
每位 AI 工程师组合不同：
- 技术方向：基座预训练 / 推理加速与部署（vLLM、量化、端侧）/ RAG 与知识库 / Agent 编排与工具调用 / 多模态（视觉、语音、视频生成）/ 具身智能与机器人控制 / AI 安全与对齐评测 / 数据工程与标注 / MLOps 与训练平台 / 推荐与搜索。
- 合作偏好：联合创始人 / 早期员工加入 / 兼职顾问 / 项目制；To B 或 To C；偏好行业（医疗、教育、法律、金融、制造、游戏、内容、出海）。
- 现实约束：全职/业余、城市、期望股权或薪资、是否已离职。
这些差异要进入名片字段与本场意图，并**真正影响打分**：例如找"端侧推理"合伙人的创业者应优先匹配推理部署方向工程师，而非 RAG 方向；想做兼职顾问的人与"找全职 CTO"的需求应降分。

## 4. 大模型延迟体验（Claude 验收发现）
上一轮报告：模型重排约 36–44s，而默认超时 25s，真实使用几乎必然降级。修复：
- **渐进式体验**：匹配页先立即展示本地引擎 Top5（标注"本地初排"），同时后台请求大模型；返回后平滑更新排序/分数/理由，并显示"已由大模型精排"；失败/超时保留本地结果并如实标注。用户在等待期间可正常操作。
- 降低延迟：请求中设置较低推理强度（如 Responses API 的 `reasoning: {effort: "low"}`，若接口不支持则安全忽略并记录）、精简输出 schema（reason ≤40 字）、candidateCount 可配置（默认 10）、限制 max_output_tokens；测量并在 match-eval 中记录优化前后实际耗时。
- 超时默认值依据实测设定（例如 60s），可配置；同一活动 + 同一意图的结果在服务端做内存缓存（TTL 可配），再次进入匹配页可秒出。
- 测试：渐进更新的状态机（local → llm / local → failed）、缓存命中、超时降级。
