# 第 9 轮：意图标签可点选 + 默认不预填 + 交友意图防丢失（用户反馈）
保持全部既有约束（≤500 行、配置化、无 emoji / 无 AI 味元素、Bonjour 风格、隐私投影、不打印 .env.local 的 Key、不结束其他占用端口的进程；用户 8787 的服务窗口由 Claude 负责重启，你验收用自己的实例）。

## 1. 用户反馈：找男朋友却推荐了女性 —— 根因与修复
Claude 核实：用户 8787 上的服务进程启动于第 8 轮之前（旧代码）。旧 /api/llm/intent 对"想找个男朋友，年龄相仿，最好也喜欢户外"返回 {"seekRoles":["男朋友"],...}，没有 mode:'dating'，前端于是走了职业匹配，结果混入女性。修复要做到即使前后端版本不一致也不会再发生：
- 前端：意图合并规则——本地 parseIntent 判定为 dating（关键词命中）时，最终意图必须是 dating，LLM 返回缺少 mode/targetGender 时以本地结果补齐；LLM 与本地对 targetGender 冲突时以本地关键词为准（男朋友→男、女朋友→女）。
- 匹配兜底：service/matcher 在 rank 前再校验一次：意图文本含交友关键词但 mode 不是 dating → 视为 dating；dating 模式下 targetGender 不符的人绝不能入选（加断言式过滤）。
- 版本一致性：/api/health 返回 appVersion（与前端 config 中的版本号对比）；不一致时匹配页与设置页顶部显示一行提示"推荐服务是旧版本，请关闭服务窗口后重新双击 启动演示.bat"，并在该状态下对 dating 只用本地规则。
- 测试：模拟旧服务返回无 mode 的意图 → 最终仍为 dating 且结果全为男性；targetGender 冲突以本地为准；版本不一致提示。

## 2. 意图标签：默认不预填，可从本场参会者标签点选
- 默认：新进入本场设置时，意图文本与标签都为空（不再从档案或默认数据预填一堆标签）。演示数据里预先报名的「AI Agent 开发者之夜」也改为空意图或最多 2 个标签，匹配页在意图为空时提示先去写一句或点选标签（不要拿空意图去调用大模型）。
- "从你的描述中读到"只显示真正解析出来的标签（可删除）。
- 新增"本场参会者常见标签"区：统计该活动参会者**本场公开投影**中的标签（职业模式：角色、行业、技能；交友模式：兴趣、生活方式、看重的价值观——仅统计已开启交友且公开这些字段的人），按出现人数排序取前 12–16 个，显示为可点选胶囊「Agent · 18 人」。点击即加入/移出意图（选中态黑底白字或亮黄），同时更新右侧预览；点选的标签要进入对应字段（角色→seekRoles，行业/技能→seekIndustries 或 skills 需求，兴趣→interests）。标签来源只用公开投影，不泄露隐藏字段。
- 职业/交友模式切换时，常见标签区随之切换。
- 测试：默认空意图；常见标签只统计公开字段且按人数排序；点选后意图字段正确；交友模式只统计开启交友的人。

## 3. 本地规则 fitReason 句式多样化
服务不可用时的本地"为什么他/她可能适合"目前句式单一（"X 和你都喜欢户外，可以从一起分享日常开始……"）。增加 6–8 套模板（配置化），按共同兴趣、生活方式、价值观、同城、年龄接近等不同证据组合选用，同一结果列表内不重复；测试覆盖。
